当前范围：本页先整理 NVIDIA《Nemotron 3.5 Super and Lightning》（arXiv:2610.38095v1）的 MTP 初始化、100B token warmup 和后训练 MTP boosting。

1. 为什么要单独训练 MTP head

推理时，MTP head 会递归使用前一位置自己生成的 hidden state；训练时如果一直喂目标模型产生的干净 hidden state，越往后的 draft position 越容易出现训练—推理状态不一致。结果是训练 loss 下降，但后位 token 的接受长度下降。

论文先冻结 backbone，只训练 MTP head；backbone 完成后训练，再冻结最终 backbone，对 MTP head 做一次 boosting，使它适配最终输出分布。

3. 初始化与 100B token warmup

Super

从 Nemotron 3 Super Base 初始化。原模型有两个 MTP head，只使用第一个 head 初始化新的递归共享 head，丢弃第二个。

Lightning

从 Nemotron 3 Super Base 的 MTP head 初始化；先融合 latent MoE projection，再将 hidden size 4096→2688、MoE intermediate size 2688→1856、路由专家 512→128，以匹配 Lightning。

Warmup

  • 100B tokens，冻结 backbone，只更新 MTP head。
  • Lightning 使用标准 2-step recursive MTP。
  • Super 使用 hidden-state mixing：第 k 步从更早 MTP steps 的状态中采样输入，模拟推理时 backbone state 与 synthetic state 的混合。

4. 后训练后的 MTP boosting

论文用对应 backbone 生成 on-policy rollouts：普通输入来自 Nemotron-Post-Training-Dataset-v2，Agent 输入来自 Nemotron-RL-Super-Training-Blends；temperature=1，序列上限 8K tokens，只对 assistant response tokens 累积 loss。

boosting 延续 hidden-state mixing，并把前一阶段的 cross-entropy 换成 LK knowledge-distillation loss，以冻结 backbone 的分布作为监督。

阶段BackboneMTP 步数目的
Super：SFT checkpoint warm start冻结4k适应 SFT 后的状态分布
Super：最终 checkpoint boosting冻结25k适配最终 post-trained backbone
Lightning：最终 checkpoint boosting冻结48k直接适配最终 backbone

6. 对训练计划的启发

  1. 把 MTP warmup 与最终 backbone 适配拆开。
  2. 把 hidden-state mixing 作为独立变量记录。
  3. 后训练数据使用 on-policy response，避免只用旧 response 做 teacher-forcing。
  4. 同时报告 teacher-forcing loss、sampled-prefix loss、逐位置 AL、draft latency、target calls 和端到端时延。
  5. 显式记录两个 rollout 数据集的混合比例；论文没有公开全部采样权重。

7. 复现缺口

  • hidden-state mixing 的采样概率和具体实现。
  • LK loss 的完整公式、温度和权重。
  • 两个 rollout 数据集的混合比例、去重和长度分布。
  • 学习率、batch、优化器、硬件和有效 token 数。
  • MTP 权重转换与 checkpoint 版本。
  • AL 提升对应的端到端 serving 配置。
结论边界：论文足以作为流程设计和变量拆分的参考，但不能单凭公开正文复现完全相同的 MTP checkpoint。
