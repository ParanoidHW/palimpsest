投机草稿模型：技术栈与思考全景

从训推一致性出发，把模型结构、数据轨迹、feature 传输、验证调度和实验决策串成一条可验证的因果链。

核心协议/指标对齐与数据训练与实验系统执行真实验收

1. 第一门槛：训推一致性

草稿模型逼近的是目标模型在具体推理协议下的行为，不是抽象的数据集分布。协议包括前向实现、权重转换、tokenizer、chat template、采样、停止规则、batch 形状，以及拒绝后 prefix/KV cache 如何更新。

三层验收：数值对齐（hidden state/logit、余弦与相对误差）→语义对齐（模板和采样一致）→轨迹对齐（使用 sampled-prefix，而非持续喂真值）。

每次运行都保存 target hash、producer commit、layer schema、dtype、随机种子，并同时记录 teacher-forced、greedy、真实 rollout 接受长度。离线与线上差异大时，先修口径再改模型。

2. 技术栈六层

模型/算子数据/轨迹损失/决策feature 传输验证调度框架交付

六层共同决定收益。更大草稿头可能增加草稿延迟；更高 feature 吞吐可能只是掩盖缓存问题；动态 verify 依赖 confidence 校准。

3. 三种生命周期

训练

检查 sampled-prefix、梯度和异步 feature 的可复现性。

Prefill

检查整段 prompt、模板、prefix 截断和 KV cache 建立。

Decode

检查少量 token、cache 追加、动态 batching、频繁验证和端到端时延。

4. 实验决策树

P0：先排除错因
  1. 重跑固定 baseline，锁定数据量和有效 step。
  2. 补 hidden state、最终 logits、checkpoint round-trip、边界 shape、框架 parity。
  3. 对照 teacher-forced、greedy、真实 rollout。
  4. 做 fixed/online feature 对照并按难例分桶。
P1：低风险搜索

逐项试 L1/CE、prefix/位置权重、confidence 校准、anchor、温度和 block size；每次只改一个变量。

P2：轨迹、结构、调度

再做 draft-induced supervision、rejected-state reuse、动态 block、候选修复和 looped drafting；先保持 verifier 合同不变。

P3：数据与在线系统

最后比较 regen、长序列、同步/异步传输、freshness window 和 curriculum，并拆分模型收益与 producer 吞吐。

5. 最小矩阵

批次问题

6. 尚未闭合的论证链

这些问题应保留为讨论入口，而不是写成确定结论：

  • 余弦相似度 >0.999 是否足以预测接受长度？还需结合 logits、相对误差和首个拒绝位置。
  • 多个采样场景能否由一个条件化草稿模型覆盖？需要比较校准成本与专用模型维护成本。
  • regen 的收益来自目标分布、温度还是长度覆盖？必须固定另外两项做因子实验。
  • feature 新鲜度、传输和训练随机性如何共同影响收敛？应记录 feature age 与 step-level host wait。
  • 接受长度在什么 draft/verify 成本比下才转成端到端收益？用 Pareto 曲线，而不是单一 accepted length 决策。
