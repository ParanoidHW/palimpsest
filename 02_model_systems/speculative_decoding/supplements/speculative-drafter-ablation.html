实验术语说明

L1 损失：逐元素计算预测分布与目标分布的绝对差，用来约束两者整体接近。

Markov 结构：用前面有限个草稿位置的信息预测下一个位置；这里的 rank 表示保留的条件化容量。

Pareto 前沿：在接受长度、草稿耗时、目标调用和端到端时延之间，没有一项继续改善而不牺牲另一项的配置集合。

Draft-OPD：让草稿模型自己生成前缀，再请求目标模型监督这些真实诱导状态的离线训练方法；它不是普通真实前缀训练的同义词。

Feature：目标模型中间层产生、供草稿模型训练使用的隐藏状态或 logits；online feature 指训练时即时生成，fixed feature 指预先生成并落盘。

1. 实验总原则

消融实验要回答“哪一个改变带来了哪一种收益”。因此要把模型算法收益与输入、目标模型特征、缓存传输和评测口径分开。

先做四项门禁：固定 baseline、补齐最终 logits 与权重转换检查、并行跑真实 rollout、完成 fixed feature 与 online feature 的同 seed 对照。任一项未闭合，都不能把 loss 或接受长度变化归因于算法。
  1. 固定目标模型、tokenizer、聊天模板、采样参数、最大长度、训练 token 数、随机种子和评测集。
  2. 每个 run 只改变一个主变量；若必须组合，先完成各自单变量实验。
  3. 同时记录 greedy 接受长度、目标模型调用次数、草稿耗时、验证耗时和端到端时延。
  4. 用真实 rollout（草稿模型自己生成前缀后再验证）确认训练期结果；teacher-forcing（使用数据集真实前缀）只能作为辅助曲线。

2. 五条算法实验线

训练目标

比较 token 分布拟合、连续前缀接受倾向和置信度校准之间的权重。重点看接受长度是否提升，同时目标模型调用和端到端时延不能恶化。

P1交叉熵 / 分布 L1 / 前缀位置权重 / 温度校准。

模型结构与容量

比较 Markov 依赖、门控结构、隐藏状态条件化和 block size。容量提升只有在草稿计算成本可接受时才有系统价值。

P1P2rank、门控、block size 3/7、草稿层数。

监督轨迹

比较真实回答、目标模型重生成回答和草稿诱导的监督。后者更接近线上前缀，但会增加目标模型特征生产和缓存成本。

P2P3rejection-focused replay、rejected-suffix state reuse、Draft-OPD 离线回放。

验证与调度

比较固定 block、动态 block、候选修复和多轮 drafting。验证器必须保持无损：目标模型仍决定最终 token，近似接受要单独标注风险。

P2confidence scheduler、候选修复、looped drafting。

数据与在线特征

比较数据来源、长序列覆盖、同步与异步特征生产。此线容易把吞吐或缓存等待误判成模型收益，必须拆开报告。

P3ground-truth / target regen、长度 4096/8192、feature freshness。

3. 最小运行矩阵

训练预算有限时先完成 B0、B9、B12、B15 四项诊断；其中 B12、B15 不需要重新训练。每个 run 使用相同训练 token 数。

编号改变项要回答的问题主要通过条件
B0当前 baseline，完整双指标固定接受率、目标调用和时延口径配置、版本、数据和评估轨迹可复现
B1-B2交叉熵 / 分布 L1 权重与温度校准分布拟合和前缀接受倾向如何取舍greedy 接受长度与端到端时延同向改善
B3-B4前两位位置权重、损失衰减早期 token 是否决定后续接受链首个拒绝位置推后，且后段质量不下降
B5-B6门控 Markov 结构、依赖容量增加条件化容量是否值得草稿开销接受收益超过新增草稿耗时
B7-B8难例重采样、置信度校准模型是否更会识别“值得继续生成”的前缀校准误差下降，目标调用次数不恶化
B9固定特征 vs 在线特征收益来自算法还是在线管线差异同 seed 下 loss 与接受曲线无显著漂移
B10-B11block size 3 / 7接受长度、草稿成本和验证成本的平衡点以端到端 Pareto 点选型，不看单一接受长度
B12teacher-forcing vs 真实 rollout训练期曲线高估了多少线上表现差异可解释并记录首个拒绝位置
B13-B14目标重生成、最大长度 4096/8192数据分布和长回答覆盖是否是主效应生成成本、特征成本和收益可比较
B15聊天模板与 token ID 对齐输入是否在本地和服务端一致首个差异位置符合预期
B16Draft-OPD 离线回放草稿诱导状态监督是否改善真实前缀真实 rollout 改善且不破坏无损验证

4. 指标与判定

质量指标

greedy 接受长度、首个拒绝位置、按位置接受率、最终回答一致性。概率接受长度或 teacher-forcing 概率长度不能替代 greedy 真实 rollout。

系统指标

草稿耗时、目标模型验证耗时、目标模型调用次数、端到端时延、tokens/s、显存、padding、缓存等待和 host-to-device（主机到设备）拷贝时间。

置信度指标

置信度校准误差（Expected Calibration Error，预测置信度与实际正确率的差异）、Brier 分数和目标调用次数。置信度损失下降但目标调用不降，不能判定调度有效。

成本指标

目标模型重生成成本、特征存储量、在线生产吞吐、缓存占用和失败重试。在线 producer 吞吐提升不等于草稿模型算法提升。

5. 归因边界

  • 前向余弦相似度高，只说明部分数值路径接近，不能直接推出接受长度或端到端加速。
  • 接受长度提升但端到端时延不变，优先检查草稿计算、验证、padding、缓存和通信成本。
  • 在线特征曲线漂移，先检查目标模型版本、特征 schema、缓存 lease、失效策略和 producer 时序。
  • 动态验证或多轮 drafting 属于推理服务状态机变化，应与纯训练消融分开。
  • 所有规划中的提升都要标记为“待实验”，不能将候选方向写成已验证结论。
