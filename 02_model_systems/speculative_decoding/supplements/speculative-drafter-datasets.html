SPEED-Bench
公开评测		Hugging Face 数据集页镜像数据集页NVIDIA 测量框架论文与 Appendix A
  • 定性 split：880 条；11 类，每类 80 条。
  • 吞吐 split：1K、2K、8K、16K、32K；每个长度 1,536 条。
  • 100K split：384 条，低/中/高熵各 128 条。
  • 定性集输入长度：论文 Appendix A 的宏平均 ISL 为 406 tokens（SpecBench 为 169）；SPEED-Bench 各类别均值/中位数见论文 Table 3。
  • 与 SpecBench 的差异：SPEED-Bench 定性集 880 条 vs 480 条；平均每类 80 条 vs 多数类别 10 条；167 个多轮 prompt、最多 5 轮 vs 80 个多轮 prompt、最多 2 轮；支持子类别、难度、长 ISL 和大 batch 固定长度吞吐评测。
  • 合计：按数据卡 v1.1 所列配置相加为 8,944 条。
  • 1K–100K 表示输入长度桶，不等于输出长度范围；实验必须记录实际启用的 split。
  • 论文 Appendix A Table 2 写为 24 个来源；Hugging Face v1.1 数据卡写为 18 个公开来源。两者可能对应论文统计口径与发布版本口径，不能直接视为同一数字。
  • 定性集覆盖 Coding、Math、Humanities、STEM、Writing、Summarization、Roleplay、RAG、Multilingual、Reasoning、QA。
  • 论文 Appendix A 还列出 Long Code Arena、RepoBench、BAMBOO、Project Gutenberg、AdaLEval、Humanity's Last Exam、MCIF 等构造方式。
  • 部分样本只保留占位文本，完整数据由测量框架从源数据获取。
  • 不是单一生成模型生成的数据集。
  • 公开卡片和论文均未给出统一的轨迹生成模型。
  • 实际 target/drafter checkpoint 由实验配置指定。
  • 配套统一测量框架，并接入生产级推理引擎。
  • 统一测量接受率和端到端吞吐。
  • 固定输入长度、并发/批大小、采样参数、精度、硬件、padding/graph 设置。
  • 记录 draft、verify、数据传输和总时延。
  • 论文 Appendix H 用吞吐 split 的真实语义输入测量 step latency，再结合不同熵域的 AL 估算域特定 speedup；随机 token 可能造成 MoE expert imbalance，不能替代真实语义输入。
AgentX
Agent 评测		AgentX 页面Methodologyv1.0 全量数据v1.0 256K 数据AgentX harness
  • v1.0：393 个 session，135,282 个 request；2026-06-21 构建。
  • 256K 变体：过滤超过 256K 输入 token 的请求后保留 68,266 个 request。
  • 长度：全量数据中位输入 142,016 token、中位输出 444 token；256K 变体中位输入 88,768 token、中位输出 376 token。
  • Agent 分支：175 个 session 含 subagent，共 1,697 个 group；group 中位持续时间 2.27 分钟，p95 为 18.5 分钟。
  • 入选 session 至少 20 个 request，使用 Claude Code 2.1.139 或更新版本，最多 10 个并发 subagent；重建输入超过 990K token 的 request 会被移除。
  • 参与者自愿开启 HTTP proxy，记录 request 到达/完成时间、输入/输出 token 数、conversation ID 和 subagent ID。
  • 公开数据不含原始 prompt、源代码、工具参数或工具结果。
  • 每个 session 的输入被表示为 64-token block 的链式 hash；相同 block ID 表示前缀复用。
  • AIPerf 将 hash block 替换为确定性的 coding / tool-use 合成 token，保留长度和前缀结构。
  • 原始客户端为 Claude Code；methodology 未公开 provider 侧的具体基础模型。
  • AgentX 不用合成内容评估回答质量；合成 token 的接受长度来自 SPEED-Bench coding 类别的实测 golden acceptance length。
  • 评测时通过 forced-acceptance 控制固定不同模型、推测方法、draft 长度和 thinking mode 的接受长度。
  • AgentX 将 trace 转成 AIPerf 可消费的 WEKA replay DAG：主 Agent 是线性链，subagent 是分支链，在依赖点 join。
  • 闭环回放：依赖完成后客户端提交下一条可执行 request；并发数是活跃 client 数，不等同于固定 HTTP batch。
  • 固定 seed 在 session 时长 25%–75% 区间选起点；使用 max_tokens=1 primer 和每条 replay lane 额外 10 个 warmup request，之后只统计 1 小时窗口。
  • 结果应同时报告吞吐、TTFT 和交互性；单一延迟值不足以描述 AgentX 运行。

SPEED-Bench 的数量和任务结构来自其 Hugging Face 数据卡（通过 hf-mirror.com 读取）；“总样本量”按各配置条目相加，不能替代对具体实验 split 的记录。AgentX 的规模、轨迹字段、重放图构造和 warmup 规则来自其 Methodology 页面；原始 provider 模型未公开，且 AgentX 不评价合成 token 的答案质量。
